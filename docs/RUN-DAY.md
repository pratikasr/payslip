# Run day

The owner's checklist for the last stage, in order. Each line says what to do and what to send back to the session that is writing the proof, the README and docs/PROGRESS.md. Submission closes 12 Oct 2026 11:59pm PT (13 Oct 12:29 IST). The scripts: pitch video in [LAUNCH.md](LAUNCH.md), demo video and mainnet runbook in [DEMO.md](DEMO.md), form answers in [SUBMISSION.md](SUBMISSION.md).

Nothing on this list spends real money until item 7, and nothing here puts a secret in the repo: client secrets go into the instance's environment file, the seed passphrase into a password manager, and neither into chat.

1. **GitHub collaborator for the judges.** On https://github.com/pratikasr/payslip/settings/access choose Add people, enter `hackathon@colosseum.com`, role Read, Add. Send back: the output of `gh api repos/pratikasr/payslip/invitations --jq '.[].invitee.login'` or `gh api repos/pratikasr/payslip/collaborators --jq '.[].login'` showing the invite or the collaborator.
2. **Zashi on three phones.** Each of the three people installs Zashi (the Verified facts in docs/TECH-DECISIONS.md record its rename to Zodl, so the store listing may show either name), opens Receive and sends you the unified address, the one that starts with `u1`, not the transparent `t1` one. Send back: three lines, name and `u1...` address, and each person's yes to having their viewing key published in the mainnet judge kit.
3. **About 0.05 ZEC in your own Zashi.** Either Swap inside Zashi from USDC, SOL or BTC, or withdraw from an exchange to Zashi's transparent address and let Zashi shield it (the balance is spendable from the shielded pool once it shows as shielded). Do not send from an exchange straight to the treasury: that would put the payroll total on a public chain and tie it to your exchange account. Send back: "funded" and the shielded balance Zashi shows.
4. **Google Cloud OAuth client.** At https://console.cloud.google.com create a project named Payslip; APIs and Services, OAuth consent screen: External, app name Payslip, your email as support and developer contact, default scopes, add your Google account under Test users; Credentials, Create credentials, OAuth client ID, type Web application, name Payslip web; Authorised redirect URI: `VERIFY: see README.md Sign-in` (the auth engineer sets it). Put the client secret only in the instance's environment file named by the runbook. Send back: the client ID (not the secret) and "redirect URI set".
5. **AWS.** From your own AWS account, run `deploy/aws/provision.sh` once, then follow the runbook in `deploy/README.md` top to bottom (VERIFY: `ls deploy/aws/provision.sh deploy/README.md` shows both; the hosting engineer writes them). Send back: the two CloudFront hostnames (app and Books) and the instance's public IP, as the script prints them, and the output of `curl -s https://<app hostname>/api/health`.
6. **GPG before the final push.** Unlock the signing key in this terminal: `echo test | gpg --clearsign -u 7C4C27F5C67D6C76 > /dev/null` (the long key id; the 12-character form answers "No public key" on this machine, checked 11 Oct 2026). List unsigned commits with `git log --format='%h %G? %s' -50 | grep -v ' G '` (on 11 Oct it printed the two session commits on top of main, 35b174c and 91e8429); re-sign everything above the newest signed commit with `git rebase --exec 'git commit --amend --no-edit -S' $(git log --format='%h %G?' | awk '$2=="G"{print $1; exit}')`, then `git push --force-with-lease`, or accept them unsigned. Send back: `git log --format='%h %G?' -20` with G on every line, or the word "unsigned".
7. **The mainnet run.** Start the screen recording first (item 8, shot list in DEMO.md), then on the hosted app: Sign in with Google; People, Add contractor for each of the three people with their `u1` address; Run payroll, the amounts, Continue, Approve; Fund with ZEC. Send the ZEC from your Zashi only when the Fund card shows the treasury address and the exact amount, and send exactly that amount; the run reads funded after three confirmations. Then Pay 3 contractors and confirm. The session watches the service and tells you when every line is confirmed; it then writes the proof, the README table and the kit. Before funding, make sure the seed backup from the runbook ran (`service/data/mainnet/payer.seed.age` copied off the instance, passphrase in the password manager). Send back: the run page URL (`https://<app hostname>/console/runs/<run id>`) and the three txids as the page lists them.

Send back: the two files, or their names and lengths (QuickTime Player, Window, Show Movie Inspector shows the duration; `ffprobe` is not installed on this machine).
